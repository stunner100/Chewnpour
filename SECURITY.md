# Security policy

## Supported versions

Chewnpour does not currently publish a version support matrix or tagged release history. Security fixes are developed against the current master branch. Older commits, feature branches, and locally modified deployments are not guaranteed to receive fixes.

If you report a vulnerability, include the commit, branch, or deployment version you tested so the maintainer can reproduce it accurately.

## Reporting a vulnerability

Please use [GitHub's private vulnerability reporting feature](https://github.com/stunner100/Chewnpour/security/advisories/new) where it is available. If that feature is unavailable, contact the primary maintainer privately through [GitHub @stunner100](https://github.com/stunner100) and request a private reporting channel.

Do not create a public issue for an unpatched vulnerability.

## What to include

A useful report should contain:

- A concise description of the vulnerability and its impact.
- The affected package, route, component, or deployment surface.
- Reproduction steps or a minimal proof of concept.
- The affected commit, version, or environment.
- Any required authentication state, configuration, or provider assumptions.
- Logs, request/response examples, or screenshots with secrets and personal data removed.
- A suggested severity or attack scenario, if known.

## Responsible disclosure

Please allow reasonable time for validation, mitigation, and coordinated disclosure. Do not access, modify, or retain data that does not belong to you. The maintainer may ask for follow-up details, coordinate a fix, and credit reporters according to their preference.

## Do not post publicly

Do not post passwords, API keys, auth tokens, database URLs, service-role keys, private user data, unpatched exploit details, or instructions that would enable attacks against users or deployments in public issues, pull requests, discussions, or repository comments.
